### How it works

ShopHub is a client-side storefront on top of the public DummyJSON products API.

```
┌──────────────────┐     ┌───────────────────────┐     ┌──────────────────────┐
│ Next.js 16 pages │ ──▶ │ Axios client          │ ──▶ │ DummyJSON API        │
│ (App Router)     │     │ global error toasts   │     │ products, categories │
└────────┬─────────┘     └───────────────────────┘     └──────────────────────┘
         │
         ▼
┌──────────────────┐     ┌───────────────────────┐
│ Redux Toolkit    │ ──▶ │ Persistence middleware│
│ 9 slices         │     │ localStorage/session  │
└──────────────────┘     └───────────────────────┘
```

### 1. Browsing

- Products load in pages as you scroll, triggered by an IntersectionObserver.
- Search is debounced, and earlier requests are cancelled with an AbortSignal so stale results never replace newer ones.
- The selected category is kept in the URL, so a filtered view can be refreshed or shared. Categories are fetched once and shared through Redux.

### 2. Cart, favourites and checkout

- The cart lives in a side drawer with quantity controls and a subtotal. Cart, favourites (stored as IDs only), theme and notifications are saved to localStorage.
- Checkout runs through four steps: shipping, payment, review and success. Shipping and payment forms are validated with Zod and React Hook Form. The payment step is a mock: no card data is sent anywhere.

### 3. Product management

- After a mock login, users can create, edit and delete products. These call DummyJSON's POST, PUT and DELETE endpoints, which return realistic responses but do not store anything, so a deleted product is removed from the local list and new products are not kept.
- Product detail, favourites, create and edit pages are protected by a route-guard hook.

### Engineering notes

- **State:** a custom Redux middleware compares slices before and after each action and debounces storage writes by 500 ms. Login state goes to sessionStorage so it clears when the browser closes.
- **Errors:** one Axios response interceptor shows toast messages for failed requests and ignores cancelled ones.
- **Types:** strict TypeScript throughout `src`, with no JavaScript files.
