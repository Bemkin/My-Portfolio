### How it works

Senselet pairs a React dashboard with a Supabase backend. The browser talks to Postgres through row-level security, and the work that needs secrets or AI runs in Edge Functions.

```
┌──────────────────┐     ┌───────────────────────┐     ┌──────────────────────┐
│ React + Vite app │ ──▶ │ Supabase Postgres     │ ◀── │ Edge Functions (Deno)│
│ Telegram Mini App│     │ 160 migrations        │     │ ai-agent, OCR, import│
│ Offline queue    │     │ 131 org-scoped RLS    │     │ alerts, billing, bot │
└──────────────────┘     └───────────────────────┘     └──────────┬───────────┘
                                                                  │
                                                                  ▼
                                                       ┌──────────────────────┐
                                                       │ Gemini model cascade │
                                                       │ → OpenRouter fallback│
                                                       └──────────────────────┘
```

### 1. Multi-tenant data model

- Every business is an organisation, and tenant tables carry an `org_id`. 131 row-level security policies across all 28 tables keep each organisation's products, sales, suppliers and logs visible only to its own members.
- The schema has grown through 160 migrations, covering product variants, multi-unit cartons, branches, purchase requests, forecasts and subscriptions.
- Stock lives on product variants with separate warehouse and workshop quantities, and check constraints stop quantities from going negative.

### 2. Stock changes through RPCs

- Adjustments and transfers go through Postgres functions such as `adjust_stock` and `transfer_stock` rather than direct table writes.
- These RPCs resolve either ID type: a variant ID is used as is, and a product ID falls back to its default variant. Lookups are always scoped to the caller's organisation.
- A multi-branch layer adds branch-level stock checks and transfers between branches.

### 3. The AI operations agent

- The `ai-agent` Edge Function exposes 33 tools to Gemini through native function calling, from read-only lookups (low stock, expiring products, best sellers, forecasts) to actions (record a sale, set an exact count, create a purchase request, reconcile an invoice against a PO).
- Tools are filtered by role before each call, so a clerk's agent can handle POS and stock counts but cannot change suppliers or approve purchases.
- Requests try a list of Gemini models in order (five in the shared AI router used by OCR and imports) and then fall back to OpenRouter. Gemini tool declarations are translated into OpenAI-style tools so function calling still works on the fallback.

### 4. Getting data in

- **Receipts:** photos are read with Gemini vision through a shared AI router, with Tesseract.js on the client.
- **Imports:** an Edge Function uses the LLM to map arbitrary CSV headers onto Senselet's product fields.
- **Barcodes:** camera scanning normalises GTINs and looks them up in catalogue APIs and a local cache, falling back to vision recognition.

### 5. Alerts, billing and Telegram

- Low-stock alerts and notifications are sent by email and Telegram from Edge Functions.
- Subscriptions are paid through Chapa, and the payment webhook verifies an HMAC signature before activating a plan.
- The Telegram bot skips repeated `update_id` deliveries so webhook retries are not processed twice.

### Engineering notes

- **Offline support:** if a stock adjustment fails while offline, it is saved to a local queue and replayed with up to five retries once the browser is back online. A badge shows how many are waiting.
- **Quality:** 266 automated Vitest tests in 30 files cover agent tools, role-based access, branch scoping, the offline queue, receipt scanning, bulk imports and barcode benchmarks.
- **Workflow:** built with an AI-assisted workflow, using LLM pair programming for schema design and feature work.
