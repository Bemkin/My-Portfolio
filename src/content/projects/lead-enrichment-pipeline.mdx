### How it works

The pipeline replaces the manual triage of news alerts with an automated qualify, enrich and route loop, while leaving approved leads in a pending state for human review.

```
┌──────────────────┐     ┌───────────────────────┐     ┌──────────────────────┐
│ Tier 1: portal   │ ──▶ │ Dedup + blocklist     │ ──▶ │ Gemini + rules matrix│
│ article queue    │     │ gate                  │     │ qualify / reject     │
└──────────────────┘     └───────────────────────┘     └──────────┬───────────┘
        ▲                                                         │
        │ quota short                                             ▼
┌───────┴──────────┐     ┌───────────────────────┐     ┌──────────────────────┐
│ Tier 2: News RSS │     │ CRM (pending) +       │ ◀── │ RocketReach + cache  │
│ 1,292 companies  │     │ Lemlist campaigns     │     │ executive contact    │
└──────────────────┘     └───────────────────────┘     └──────────────────────┘
```

### 1. Qualification

- Candidate articles come from the client's review queue, alternating between news articles and alerts.
- A dedup and blocklist gate rejects companies that are already leads before any paid lookup happens.
- Gemini reads each story, and a rules matrix of more than a thousand lines excludes cases that do not fit the client's criteria, such as regional place names, traffic accidents and non-adverse roundups. Each rejection carries a classification code.

### 2. Enrichment

- Qualified companies are matched to a C-suite or VP contact through RocketReach, reusing a local enrichment cache wherever possible.
- All RocketReach calls go through a single serial queue with exponential backoff that respects `Retry-After`, and the pipeline detects long lockouts instead of hammering the API.
- A credit manager enforces a daily budget of 25 lookups and reports usage through `npm run stats`.

### 3. Filling the quota

- The daily target is a random number between 20 and 22, configurable through environment variables.
- If the portal queue cannot meet it, a Tier 2 waterfall scans 1,292 monitored companies for crisis terms on Google News RSS, enriches the matches and injects them as direct leads.

### 4. Routing

- Approved leads stay in a pending state and are split evenly between the client's account owners.
- Leads are pushed into Lemlist campaigns with dedup, a domain firewall and bounded concurrency.
- Where the CRM has no API for a step, Playwright drives the browser using a persistent login session.

### Engineering notes

- **Service:** a Fastify server exposes `/enrich`, protected by a shared-secret header, plus health, stats and Lemlist routes. Production runs on Render.
- **Scheduling:** node-cron runs the pipeline on weekdays, with a catch-up mode for missed runs and a once-only mode for manual runs.
- **Maintainability:** dozens of one-off scripts were consolidated into five standardised CLIs for audits, purges, reviewer assignment, the Tier 2 waterfall and cache management.
- **Safety:** a post-run audit checks that every injected lead is still pending before anyone reviews it.
